# 《明日随访》项目实现文档 · 04 册：任务块与测试部署

版本：1.1（2026-09-12）。保留T01–T33父任务索引，将大任务拆为可交付子任务。依赖以表中的ID为准，不再假设表格行序就是全部依赖。工作量是实现参考，不能仅用“半天一天”掩盖未完成验收。

## 1. 工程准备与共同完成定义

Node版本须满足所锁Vite的engines；2026-09-12核对的Vite指南要求20.19+或22.12+，不再只写Node≥20。T01锁定实际使用的Node、包管理器、Vue/Vite/TS/Router/Pinia/Vitest/Playwright版本并提交lockfile供项目内复现。后续不在不同任务间各自安装latest。

参考：[Vite Getting Started](https://vite.dev/guide/)。音频任务可使用ffmpeg/ffprobe；若启用特定占位TTS再安装其工具，不把Python或在线服务列成字幕纵切的启动条件。

每子任务必须完成：声明文件/数据落点；处理正常及明确列出的失败分支；运行对应验收；说明实际通过/未通过项。必要的测试文件由任务一起创建，不假设仓库里早已存在。无须为纯排版写镜像测试，但不能用构建通过替代状态与推理判定。

脚本约定：`npm run typecheck`、`npm run build`、`npm run check:content`、`npm run test:unit -- <file>`、`npm run test:e2e -- <file>`。T01配置这些命令。尚无测试文件时不要写“空测试通过”作为里程碑成果。

## 2. 音频生产：先保证能解，再保证好听

### 2.1 资产与字幕

- 11个唯一资产AUD01.mp3–AUD11.mp3。AUD02–07从CHANNEL_03_MASTER连续交班场景切出；CHANNEL_03_FULL是它们正确重组的逻辑播放id，不另算配音条数。
- 第一版全流程使用客观字幕、跨切点说明与波形占位。UI隐藏AUD序号，只显示片段代号。
- 语音、停顿、音效用结构化cue表示。speech用真实文件长度；pause为确切毫秒；sfx声明相对哪个cue插入。不用“字数×语速估时再silencedetect猜偏移”。
- 环境声可自录或合成。钟、药车双音、门槛脚步、台灯按下回弹须可区分；不是为了省录音成本而把粗糙噪声直接视为合格成品。

### 2.2 连续场景与切分

制作顺序：录音启动/报时 → AUD02台词 → CART_DOUBLE（在规定点切开）→ AUD03台词 → FOOTSTEP_PASS（切开）→ AUD04台词 → AUD05台词 → LAMP_PRESS_RELEASE（切开）→ AUD06台词 → AUD07台词 → 录音停止。

边界关系来自02册manifest。每个跨切点音效只生成一次；左右片段取同一波形的两个相邻区域，保证实际可拼接。客观字幕分别说明前后半段和录音起止，不能让不听声音的玩家缺失信息。拼接证明是开始、三对连续声响、停止标记共同限定唯一顺序。

先输出PCM master及精确cut sheet，再编码MP3，并从**最终成品文件**计算timings与peaks。试听拼接处是否因编码延迟产生可闻断点；完整重组回放可使用预合成master版本，仍视为同一场景的派生产物，不新增独立台词资产。

`timings.json`条目：assetId、durationMs、captionCues[{startMs,endMs,text}]、anchorCues[{id,startMs,endMs,side}]；峰值JSON含durationMs、400个归一化峰值及引用同一锚点。不得将字幕对齐到TTS输入的估计时间。

### 2.3 占位、正式版与替换

TTS仅为可替换生产工具，玩家端无TTS接口。可使用开发机已有工具生成占位；若使用edge-tts等非官方在线工具，应视为可能不可用的可选路径。正式版优先自录；采用其他音源时按其当前使用条件确认，不在文档中承诺某厂商免费配额或默认可商用。

替换真人录音后，重新生成master、切点、字幕timings和波形。必须保留先后与接续关系，不要求演员模仿旧占位时间轴到±0.5秒。全量音频生成失败时仍可运行字幕版，错误输出明确列出失败资产。

音量统一后人工试听；不靠左右声道、高频、突响或静默长度解谜。AUD09开关在12秒，整段18秒。其他targetSecRange是自然演出的预算，不能为了凑范围补几十秒空白。

Playwright路径：

1. `vertical-slice.spec.ts`：从P00起走SELF和REPLAY各一次，分别用本地文件确认/快照，文字确认AUD01，恢复许棠。
2. `full-paths.spec.ts`：SELF/REPLAY×A/B/C六种完整路径，公共操作抽helper复用；主流程不得从SURGERY_READY夹具开始，以免遗漏前期门槛。
3. `recovery.spec.ts`：在p1、p6、a1、p8草稿中刷新；导入决策前导出件；继续到同一结果。恢复操作允许额外IMPORT事件，只比较原日志前缀。
4. `fallback.spec.ts`：不播放音频、拒麦、录音保存失败转文字、无纸面、图片/外链失败，均可完成C；没有Web Locks时正确进入临时模式而非静默覆盖。
5. `ending-fixtures.spec.ts`：领域层生成各结局夹具，只用于快速回归最终面板与显示，不能替代完整路径。

浏览器人工检查：桌面Chromium、Firefox、Safari；至少一次实际iOS/Android手机。确认录音格式、按住中断、离页/后台释放、首播手势、200%字体和键盘焦点。Playwright WebKit不是实际iOS硬件麦克风验证。

多窗口：支持环境使用Web Locks独占持久写入；通知条只是通知。一个窗口已推进时，旧窗口下一动作必须被拒绝并提供重新载入，不自动混合事件。参考：[MDN Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)。

## 4. 静态部署与交付

默认目标GitHub Pages，项目仓库路径与用户站点根路径分别测试。`SITE_BASE`为构建输入，规范化为`/`或`/实际仓库名/`；所有资源经import或import.meta.env.BASE_URL引用，不能散落`/arggame/`硬编码。Hash路由刷新不需要业务路由服务器重写。

Pages采用GitHub Actions artifact发布：checkout → setup Node（锁定版本）→ npm ci → typecheck/check:content/unit/build → upload-pages-artifact(dist) → deploy-pages。Pages Source设为GitHub Actions；workflow需contents:read、pages:write、id-token:write、github-pages环境与并发配置。**不混写“deploy-pages部署到gh-pages分支”**，那是另一种发布方式。

实际action版本与workflow参数在T32按官方文档落盘并锁定；示例入口：[Vite静态部署/GitHub Pages](https://vite.dev/guide/static-deploy.html)。正式发布前必须已有可预览的dist和通过的构建记录；本轮文档修订不执行仓库推送或站点发布。

发布验证：本地production preview正常；项目base和根base均无资源404；HTTPS下录音/存档能力正确；核心JSON默认随包可用；外部文学链接可选，本站短摘录不依赖它。不要用file://双击dist作为支持的运行方式。

性能预算：先加载主界面、文字内容和当前章节；音频按需加载，峰值预计算。目标首屏核心资源≤600KiB gzip、单张氛围图≤300KiB；预算超出时根据构建报告定位，不把预算当成已测成绩。版本更换导致旧标签页资源失效时显示刷新/导出入口，不演成叙事污染。

## 6. 试玩统计与体验判定

本机统计字段：随机sessionId、chosenBranch、ending、总活跃分钟、每章活跃分钟、各题首次打开/提交/通过时间、失败次数、提示最高级、未完成离开点。语音blob、原始音频、玩家自由文本和个人身份不进入报告。暂停、后台、P00停留从活跃时间扣除。

测试者在结束或退出时主动点击“导出试玩报告”，自行交给组织者。组织者本地合并JSON生成按关卡汇总的表；没有后端自动采集，也不借此引入邮箱/热线。

5人是第一轮校准样本，目标中位180–240分钟，并观察是否3人及以上在同点无有效进展超过15分钟。还要问：许棠为何需要继续随访？两界面为何不能算两份独立依据？为何切D？答不清说明因果表达有问题，即使已经点到结局也需修。

时间明显偏短时先查提示是否直接泄解、证据是否提前发放、是否存在跳关；确需加厚则增加有不同信息的原始材料和行动后果。偏长先查导航和重复劳动，删除强制复读，不削掉必要证据。熟练玩家或使用完整提示者低于目标不作惩罚。

## 7. 风险与发布完成定义

| 风险 | 已约定处理 |
|---|---|
| 分支日志语义混淆 | ReviewCause及六条完整路径；回放不代签 |
| 数据/页面各自定义开放 | availability唯一函数；运行时命令重复校验 |
| 录音无法唯一排序 | 连续master跨切点、边界约束、720顺序检查、纯文字试解 |
| 证据过早讲出答案 | 原始资料与生成结果分开；测试者观察发现过程 |
| 多窗口覆盖或导入缺录音 | 独占写锁/临时模式；文字声明保底；schema及前缀检查 |
| TTS不可用或真人替换破坏锚点 | 无音频版可通；音源可换、整条时间轴重建 |
| 原文不可达 | 站内已核对短摘录默认显示；不以外链成功作为gate |
| 3–4小时未达到 | 按真实试玩分解推理/导航/阅读时间，不给玩家加等待锁 |
